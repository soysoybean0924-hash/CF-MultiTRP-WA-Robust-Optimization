# WMMSE-ADMM reproduction and Chasi ideal-CSI experiments

This directory keeps the original Python research package together with new MATLAB and reproduction work. The original package is associated with Zaher *et al.*, “Learning-Based Downlink Power Allocation in Cell-Free Massive MIMO Systems,” IEEE TWC 22(1), 174–188 (2023). Its license statement appears below in the original README. Original Python sources have not been replaced.

**Current scope (2026-10-24):** The original sum-SE/PF scalar power allocation core, pilot MMSE estimate, and MR/RZF statistics have been translated and checked on one shared 16-AP/20-UE, 100-channel-realization input. Separate Python and MATLAB 2000-setup CDF data files exist locally; they use independently generated random realizations, and the paper-style CDF figure has not yet been generated. The corrected Chasi scene uses 7 sites, 21 co-sited sector TRPs, 210 UEs, and two serving TRPs per UE. Its fixed-direction single-stream baseline ran for 100 outer iterations but every ADMM inner loop hit its limit. Its centralized two-stream complex-matrix ideal-CSI sum-SE solver ran 60 outer iterations and continued to 70; every inner ADMM solve met the recorded residual thresholds, while the WMMSE outer loop stopped at its iteration limit and remains budget sensitive. The final rate and TRP powers were recomputed by a separate evaluator. The Chasi channel combines partial TR 38.901 UMi large-scale formulas with a documented simplified small-scale model, not a complete TR 38.901 channel. A controlled-observation nominal CSI path and a cross-RB PF matrix branch have passed small tests and each of the four CSI × objective branches has run **one** 210-UE outer iteration as an entry diagnostic; no formal four-way CSI gap has been established. DNN is outside this project's current WMMSE-ADMM research scope.

## Layout and reproducible entry points

- `main_DNN.py` and the other top-level `.py` files: untouched original Python package. The published entry expects external AP positions, datasets, and trained models; its default 2000-setup preallocation exceeds available memory here.
- `matlab/`: scalar WMMSE-ADMM sum-SE/PF, pilot-MMSE, MR/RZF statistics, independent original-scene generator, checkpointed CDF runner, paired-input diagnostics and plotting scripts.
- `chasi-matlab-core/`: shared Chasi scene/channel generator, coherent two-TRP single-stream and two-stream solvers, small numerical checks, checkpointed full-scale entries, and a saved-result verifier. Requirements, propagation formulas, and assumptions are recorded in `reproduction/report/chasi_joint_scene_design.md`; actual run and stop evidence is in `reproduction/report/chasi_joint_phase_status.md`.
- `reproduction/python/`: project-local dependency lock, original-source in-memory smoke wrapper, and small deterministic paired-input fixture. `original_smoke.py` regenerates the ignored large H/Hhat MAT input without modifying original source.
- `reproduction/inputs/`: paired fixtures; the 7 MB original-scene H/Hhat MAT is regenerated by the smoke wrapper and excluded from Git. `ideal_csi_branch.py` then regenerates the ideal-CSI diagnostic coefficients from that exact H.
- `reproduction/matlab/`, `reproduction/chasi_ideal/`: logs, small result MAT files, and actual MATLAB figures.
- `reproduction/report/status.md`: model assumptions, original-image requirement table, numerical evidence, failed attempts, and remaining work.

From this project directory on Windows, create a Python 3.9 virtual environment and install `reproduction/python/requirements.lock.txt`. Then run `./.venv/Scripts/python.exe reproduction/python/diagnostic_fixture.py` and `./.venv/Scripts/python.exe reproduction/python/original_smoke.py`. For MATLAB R2026b, run `matlab -batch "addpath('matlab'); run_diagnostic_fixture"`, `matlab -batch "addpath('matlab'); run_statistics_comparison"` after generating the smoke MAT, and `matlab -batch "addpath('chasi-matlab-core'); run_chasi_ideal"`. In this environment MATLAB required the authorized elevated project-operation context; ordinary sandbox startup returned `File system inconsistency`. The Chasi script writes its actual objective/residual plots and MAT data to `reproduction/chasi_ideal/`.

The one-setup input and synthetic fixture are **diagnostics**, not the formal paper CDF. The original Python nonideal-CSI model uses `Hhat` for beam directions and true `H` for statistical performance coefficients. The Chasi ideal-CSI baseline uses the same true snapshot for optimization and evaluation, with fixed single-stream transmit and 4Rx receive directions. Read the report before comparing their numbers.

Formal WMMSE CDF runners are `reproduction/python/run_formal_batches.ps1` and `matlab/run_formal_cdf_batches.ps1`. They resume project-local checkpoints and run at most 25 Python or 100 MATLAB setups per fresh process to limit memory. The complete 2000-setup MAT arrays exist locally under `reproduction/python/` and `reproduction/matlab/`; they are excluded from Git because they are regenerable and larger than the compact logs. `matlab/plot_original_cdf.m` requires both complete MAT arrays; its actual figure remains pending. The published DNN comparison curves require external trained models and are outside this WMMSE-ADMM scope.

For the corrected Chasi ideal-CSI matrix solve, run `matlab -batch "addpath('chasi-matlab-core'); run_joint_matrix_ideal(10,60,150,'formal_adaptive60',0.1,'',0,true)"` from this directory to start from scratch. The actual 60-iteration result was resumed through three, ten, and thirty-iteration checkpoints; see `reproduction/report/chasi_joint_phase_status.md` for exact commands, stop status, data and figures. `verify_joint_matrix_saved('formal_adaptive60')` independently recomputes its final rate and power from the regenerated true channel. The full checkpoint and 16 MB result MAT stay local; the CSV, logs and MATLAB figures document the uploaded run.

For the new paired diagnostic, run `matlab -batch "addpath('chasi-matlab-core'); prepare_chasi_paired_inputs"` once, then `run_chasi_paired_branch('ideal_sumse',1,'diagnostic1')` and the other branch names `nominal_sumse`, `ideal_pf`, `nominal_pf` with distinct output tags. The frozen input manifest and numerical channel checksums are under `reproduction/chasi_paired/inputs/`. Existing input or result names are protected against overwrite. See `reproduction/report/chasi_outer_budget_analysis.md` for the shared stopping rules and `reproduction/report/chasi_paired_stage_status.md` for exact one-step evidence, the controlled error model, storage limits, and why these runs are not final CSI-gap results. Formal four-way runs need at least 1 GB more free D-drive space for resumable results and checkpoints; current free space is about 137 MB.

Learning-Based Downlink Power Allocation in Cell-Free Massive MIMO Systems
=====================================================================================================

This code package is related to the following scientific article:

Mahmoud Zaher, Özlem Tuğfe Demir, Emil Björnson, Marina Petrova, “[Learning-Based Downlink Power Allocation in Cell-Free Massive MIMO Systems](https://arxiv.org/pdf/2109.03128.pdf),” IEEE Transactions on Wireless Communications, vol. 22, no. 1, pp. 174-188, Jan. 2023.

The package contains a simulation environment, based on Python, that reproduces the numerical results in the article. Please read the "Content of the Package" section below before trying to run the code.

We encourage you to also perform reproducible research!


## Abstract of Article

This paper considers a cell-free massive multiple- input multiple-output (MIMO) system that consists of a large number of geographically distributed access points (APs) serving multiple users via coherent joint transmission. The downlink performance of the system is evaluated, with maximum ratio and regularized zero-forcing precoding, under two optimization objectives for power allocation: sum spectral efficiency (SE) maximization and proportional fairness. We present iterative centralized algorithms for solving these problems. Aiming at a less computationally complex and also distributed scalable solution, we train a deep neural network (DNN) to approximate the same network-wide power allocation. Instead of training our DNN to mimic the actual optimization procedure, we use a heuristic power allocation, based on large-scale fading (LSF) parameters, as the pre-processed input to the DNN. We train the DNN to refine the heuristic scheme, thereby providing higher SE, using only local information at each AP. Another distributed DNN that exploits side information assumed to be available at the central processing unit is designed for improved performance. Further, we develop a clustered DNN model where the LSF parameters of a small number of APs, forming a cluster within a relatively large network, are used to jointly approximate the power coefficients of the cluster.

## Content of the Package

The main_DNN.py script is responsible for generating the figures in the article. It can be used to generate datasets that are utilized to train and test the neural networks (NNs) proposed in the article and solve the WMMSE problems using the related functions in the code package. <b>To generate data, the parts responsible for utilizing the trained models in the main_DNN.py should be commented out and the required variables for the models' input and labelled output saved.</b> The file APLocation_Generation.py is used to generate the AP positions that should be saved and kept fixed afterwards throughout the simulations.

To train the DDNN and DDNN-SI models, the Distributed_FFNN.py can be used after generating the required datasets. The Clustered_FFNN.py is used for the CDNN model. <b>In these two files, the scaler.pkl should be saved once for a given simulation setup (dataset).</b> Please note the names of the datasets and trained NN models while saving in order to use them in the main script and the functions that it utilizes (Predictions_DDNN.py, Predictions_CDNN.py).


## Associated datasets

The datasets are associated with the non-orthogonal pilot assignment case in the article. The input and labelled output for training the models therein, and the computed SE performance for the conventional optimization approaches are provided. All files, except for the 'APpositions' file should be grouped in a folder named 'pAssign_storage' and located in the same folder as the code package.
