# 关于误差如何建模

**SRS测量过程产生的误差并非“通用非理想CSI”的简单特例，它在误差的“跨用户相关性”和“时间结构的可预测性”上具有特殊结构**。通用鲁棒模型（如范数有界误差）通常假设误差独立或最坏情况有界，而SRS误差的导频污染分量是用户间耦合的，时效性分量是随SRS周期与用户移动性演化的。建模的关键在于把这两类结构显式分离，而非用一个笼统的误差椭球覆盖。

### SRS误差区别于通用非理想CSI的特殊结构

通用非理想CSI模型通常只关心“估计值与真实值之差有多大”，不关心这个差是怎么产生的。但SRS测量产生的误差有两个通用模型不刻画的结构：

**（1）导频复用导致的误差在用户间相关，而非独立。** 多用户SRS在相同的时频资源上以不同循环移位或梳齿发送时，到达非服务TRP的导频会相互叠加。一个TRP估计某用户信道时，其他用户的SRS泄漏构成污染分量。这意味着误差向量不是该用户独有的，而是与同一资源上复用用户集合的功率、空间位置耦合。文献中讨论大规模MIMO多向中继时明确指出，导频污染与信道老化具有“累积的有害效应”，且这种效应在基站天线数趋于无穷时仍不可消除。通用范数有界模型无法表达“用户A的误差大是因为用户B的导频功率高”这种跨用户依赖。

**（2）时效性误差具有随SRS周期和移动性演化的时间结构，而非静态随机扰动。** SRS是周期或半持续发送的，两次测量之间的信道因用户移动和多普勒效应发生老化。Cell-free Massive MIMO的研究中将信道老化效应显式建模为时间相关项，SINR随测量时刻与使用时刻的间隔增大而显著下降。通用统计CSI模型（如高斯误差）通常假设误差方差固定，但SRS时效性误差的方差随SRS周期、用户速度、载频（2.6/3.5 GHz）共同决定。此外，SRS跳频图案（hopping pattern）本身也会引入特有的老化模式，有研究将“SRS跳频图案导致的信道老化”列为实际系统缺陷之一。

**（3）观测噪声分量相对“常规”，但受SRS带宽与功率控制影响。** 这部分最接近通用估计误差，但SRS的频域带宽配置和上行功控决定了不同用户的信噪比差异，使得误差方差在用户间不均匀。真正需要区别于通用模型的是前两项。

### 建议的误差建模框架：分层结构化模型（建模体现

不建议用一个混合高斯或单个误差椭球来“统一”覆盖所有来源。更合理的做法是**按误差来源分解为可解释的项**，并让协同资源分配算法利用这种分解。

**第一层：导频污染项（用户间耦合，结构性）**

将TRP rr 对用户 kk 的估计误差中的污染分量写成对复用用户集合 SrSr 的求和形式。一种可操作的抽象是：误差协方差矩阵包含一个由复用用户大尺度参数（路径损耗、到达角分布）决定的外积项。具体地，若用户 jj 与 kk 在同一SRS资源上复用，则 jj 的导频对 kk 的估计污染近似正比于 pjhrjhrjHskpjhrjhrjHsk 的投影（取决于循环移位正交性）。在资源分配层面，这意味着：**服务TRP选择与SRS复用模式是耦合的**——把两个空间上接近的用户放在同一SRS资源上，污染会加剧；分到不同梳齿则污染降低但SRS开销增加。你的计划中“用户中心服务关系选择”如果忽略这个耦合，鲁棒约束就无法区分“因为复用而差”和“因为信道本身差”。

**第二层：时效性项（时间相关，可预测但需参数）**

用一阶高斯-马尔可夫过程刻画SRS测量时刻 t0t0 到调度使用时刻 t0+Δt0+Δ 的信道演化。误差方差可写为 σage2(Δ)=2σh2(1−J0(2πfdΔ))σage2(Δ)=2σh2(1−J0(2πfdΔ)) 的形式（J0J0 为零阶贝塞尔函数，fdfd 为最大多普勒频率）。你的场景载频2.6/3.5 GHz、用户速度未给定，但SRS周期 ΔΔ 是可控参数。关键建模决策是：**SRS周期是否作为优化变量**。如果是固定的，时效性误差是一个已知方差的加性项；如果可调，它就与导频污染形成折中（周期短→时效性好但SRS开销大且复用更密→污染可能加剧）。

**第三层：观测噪声项（对角/近对角，常规）**

这一项可以用常规的估计误差方差 σn2/(Pk⋅NSRS)σn2/(Pk⋅NSRS) 量级刻画，其中 PkPk 受上行功控影响，NSRSNSRS 是SRS占用的资源元素数。在鲁棒设计中，这一项可以作为基础不确定性半径，与上面两项叠加。

### 对鲁棒设计“链路差异化”的直接含义

一旦按上述结构分解，你计划中提出的“链路差异化的鲁棒设计”就有了具体抓手：

- **对导频污染主导的链路**（如边缘用户、SRS复用密集区域），鲁棒约束应作用于**服务TRP选择**和**SRS资源分配**的联合层面，而非仅仅收紧波束的误差椭球。因为污染的本质是“选错了TRP，那个TRP上听到的主要是别人的导频”。

- **对时效性主导的链路**（高速用户、长SRS周期），鲁棒约束的强度应随 ΔΔ 和用户速度自适应，并可以考虑在调度中优先服务“信道信息即将过期”的用户，或对这类链路预留更大的功率余量。

- **对噪声主导的链路**（近点、高SRS SINR用户），可以采用较轻的鲁棒约束，避免无差别的保守性浪费功率。

  这样，你的鲁棒设计就不是“对所有链路施加统一的误差椭球”，而是**根据SRS误差的结构性来源选择不同的保护对象**——这恰好回应了上一轮指出的“保守性陷阱”问题。

### 需要在你计划中明确的一个参数锚点

你目前没有给出假设的**SRS周期**和**调度周期**。这两个数值直接决定时效性误差的量级。建议在场景假设中明确（例如SRS周期20ms、调度周期1ms，则老化间隔约20个调度时隙），否则时效性建模缺乏可复现的锚点。同时，SRS的梳齿数（comb size）或循环移位复用因子也应给出，它决定了导频污染的用户间间隔是2、4还是更多，直接影响第一层耦合结构的稀疏程度。



一篇更相关的文献是 KTH 的硕士论文 **《Channel Estimation Error Model for SRS in LTE》**（2011）。它的核心思路正是你需要的：**将 SRS 的信道估计误差建模为一个标准差，该标准差是目标用户接收功率、干扰用户（同小区及邻小区）接收功率以及背景噪声的函数**，并以此在系统仿真器中作为噪声施加于理想信道上。这篇文献直接讨论了 SRS 复用（CDM）带来的用户间干扰，并明确指出了“干扰是主要误差来源”这一结论，这与你想利用的“误差在用户间相关”的结构是一致的。

# 关于鲁棒设计





若在开题中补充上述“分层不确定集+分变量约束+保守性消融”的框架，并说明大尺度信息的可获取性假设与求解的交替结构，这一部分的方法论就站得住。

SRS误差结构（导频污染项用户间耦合、时效性项随SRS周期和移动性演化、噪声项近对角），建议采用**分层不确定集 + 分变量施加约束**的框架，而非对所有链路施加统一误差椭球。

**第一层：不确定集按误差来源分解，而非单一椭球**

- **导频污染项**：用**结构化不确定集**——误差协方差 E[epilot(epilot)H]E[epilot(epilot)H] 的外积结构由同SRS资源复用用户集合 SrSr 的大尺度参数决定（路径损耗、到达角分布）。在优化中，这一项的影响可以通过**约束服务TRP选择与SRS复用模式的联合决策**来管理，而不是仅收紧波束的误差半径。具体地：若某用户被选为服务TRP的链路恰好处于SRS复用密集区，则该链路的污染方差上界较大，优化时应优先考虑更换服务TRP或调整该用户的SRS梳齿分配（如果SRS配置是可控变量）。

- **时效性项**：用**参数化统计不确定集**——方差 σage2(Δk)σage2(Δk) 是SRS周期 ΔkΔk 和用户速度 vkvk 的已知函数（一阶高斯-马尔可夫或贝塞尔函数形式）。这一项不引入“最坏情况”，而是作为**已知方差的加性扰动**进入鲁棒约束，约束强度随 ΔkvkΔkvk 自适应。

- **噪声项**：用**范数有界或对角椭球**——方差由SRS接收功率和占用资源元素数决定，是最常规的一项，作为基础不确定半径。

  **第二层：鲁棒约束分变量施加，而非统一加在波束上**

- **服务关系选择**：对污染主导的链路，鲁棒性体现在“不选污染方差上界超过阈值的TRP作为服务节点”，或在服务TRP集合选择时引入污染协方差的惩罚项。这是离散决策层面的鲁棒化。

- **波束配置**：对时效性主导的链路，波束设计采用**统计鲁棒**（基于误差协方差而非最坏情况），因为时效性误差近似零均值高斯，最坏情况约束会过度保守。对噪声主导的链路，可采用较轻的范数有界约束。

- **功率分配**：鲁棒功率优化在WMMSE/ADMM框架下，将各链路的误差方差作为**加权因子**进入等效信道增益的下界估计，而不是对每条链路施加相同百分比的功率回退。差异化体现在：污染方差大的链路获得更大的等效噪声项，从而在功率分配中自然获得更多保护，但不必对所有链路统一回退。

  **第三层：保守性管理机制**

- 设置**鲁棒强度调节参数** ϵkϵk（链路 kk 的约束松紧），并给出其与SRS SINR、SRS周期、复用密度的映射规则（例如 ϵk∝σage2+σpilot2ϵk∝σage2+σpilot2），而不是全局固定 ϵϵ。

- 在评价时增加一个消融基线：**同样的协同框架但用估计CSI直接优化（不做鲁棒约束）**，用以分离“协同增益”与“鲁棒增益”，并观察鲁棒设计是否在5% CDF上改善的同时没有显著恶化平均功率效率。如果出现“边缘改善但平均功率大幅上升”，则说明差异化规则需要调整（例如对噪声主导链路放宽约束）。
